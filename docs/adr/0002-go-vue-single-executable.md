# 使用 Go 与 Vue 构建单个可执行文件

第一版优先在 Windows 上交付单个可执行文件，后续支持 Linux Docker 单实例部署，因此选用 Go 后端，将 Vue 3、TypeScript、Vite 构建的前端静态文件嵌入应用，由同一服务提供页面与接口。选择 Go 主要考虑单程序交付路径；相比 TypeScript/Node 全栈，接受维护两种语言的成本，内存目标仍须实测验证。

建组涉及搜索多选、临时选择状态、新增词条后继续建组及取消操作，因此选择 Vue 管理客户端交互，代替服务端模板加 htmx 的路线。接受前端构建工具链和接口维护成本，正式运行不需要独立的前端 Node 服务；单文件交付指应用程序，持久数据保存在程序之外。

Windows 默认将数据放在程序旁的 `data` 目录，形成便携布局，允许显式指定其他数据目录。该选择便于一起移动程序和数据，同时要求默认位置可写；不默认把数据写入用户 AppData 目录。
