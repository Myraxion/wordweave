# 使用 SQLite 保存生词本数据

生词本是单用户、单实例应用，且关系组编辑和词条删除需要跨记录的原子操作，因此选择应用内的 SQLite，以事务保存词条、关系组及成员关系，免去独立数据库服务的运行与维护成本。相较 PostgreSQL 等客户端/服务器数据库，接受 SQLite 的单写入者约束；当前不为高并发或多个应用实例共享数据库做设计。

采用不依赖 cgo 的 `modernc.org/sqlite` 驱动，使用 `database/sql` 与集中维护的参数化 SQL，围绕完整业务操作划定事务边界。相较 ORM，接受手动维护查询和结果映射的成本，以便直接检查 SQL 与事务行为；关键规则通过数据库集成测试验证。

数据库及相关文件放在外部可写数据目录，Windows 默认位于程序旁的 `data` 目录，后续 Docker 部署持久化数据目录。启动时执行随程序发布的编号 SQL 迁移，升级已有数据库前生成一致性备份；待执行迁移与版本记录在一个事务中完成，失败则停止启动，拒绝自动降级。选择 SQLite 本身不构成对搜索性能或 100 MiB 内存目标的保证。
