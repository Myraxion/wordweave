# 技术选型

状态：已于 2026-11-03 经用户整体确认，作为第一版技术选型基线。本文记录技术取舍，不替代[功能需求](product-requirements.md)。性能与交付验证属于后续实施工作，尚未执行。

## 已确认的选型约束

- 优先级：正确可靠、简单可维护、满足内存预算，再考虑进一步优化。不为少量内存收益明显增加代码复杂度。
- 第一版优先在 Windows 上运行验证，优先交付单个可执行文件，默认仅供本机访问；Docker 属于后续交付阶段，采用 Linux 单实例部署，数据目录持久化到容器之外，默认部署示例仅将端口发布到宿主机回环地址。
- 初步目标：正式运行时，后端服务及其数据库相关进程合计常驻内存约不超过 100 MiB；这是待实测的目标，暂不是硬性验收门槛。浏览器页面内存单独测量，开发服务器及构建工具不计入运行预算。
- 代表性验证规模为 1 万个词条、3 万个关系组，多数组含 2～10 个成员；这不是产品数量上限。
- 扩展性主要指未来增加导入导出、复习、自动查词等业务功能，以及修改现有规则。这些示例不改变第一版功能范围；暂不为多用户、高并发、分布式部署或插件系统预建基础设施。
- 用户没有必须沿用的语言或框架，也没有语言偏好。

## 已确认的技术栈

| 部分 | 选择 | 约束与取舍 |
| --- | --- | --- |
| 后端 | Go | 适配单程序交付目标，内存是否达标仍需实测 |
| HTTP 服务 | 标准库 `net/http`，HTTP＋JSON 接口 | 按接口处理、业务规则和数据访问组织职责，暂不引入 Gin、Echo 等框架 |
| 数据库 | SQLite | 应用内访问持久数据，通过事务保证跨记录操作原子性 |
| SQLite 驱动 | `modernc.org/sqlite` | 不依赖 cgo，减少 Windows 与 Linux 构建所需的 C 工具链配置 |
| 数据访问 | `database/sql`＋手写参数化 SQL | SQL 集中在数据访问模块，事务围绕完整业务操作；第一版不引入 ORM 或 SQL 代码生成工具 |
| 前端 | Vue 3＋TypeScript＋Vite | 使用组件和客户端状态组织交互，接受前端构建工具链及接口维护成本 |
| 前端导航和状态 | Vue Router，组件内状态及组合式函数 | 暂不引入全局状态库；有明确跨页面共享状态需求时再评估 Pinia |
| Windows 交付 | 单个可执行文件 | 前端构建产物嵌入应用，由同一服务提供页面和接口；数据库是运行时产生的外部可写数据 |
| 后续 Docker 交付 | Linux 容器，单应用实例 | 持久化数据目录，保持个人使用范围，不因容器化而引入多实例共享数据库 |

前后端及交付方式见 [ADR-0002](adr/0002-go-vue-single-executable.md)，数据库选择见 [ADR-0003](adr/0003-sqlite-storage.md)。

## 便携数据目录

- Windows 默认将数据保存到可执行文件所在目录下的 `data` 目录，按可执行文件位置解析，不依赖启动时的工作目录。
- 单个可执行文件包含程序、前端资源和随版本发布的迁移脚本。数据库及升级备份属于外部可写数据，移动程序与数据目录即可保留便携布局。
- 允许通过启动参数或环境变量指定其他数据目录；后续容器使用挂载的数据目录。
- 不使用用户 AppData 目录作为默认数据位置。

## 数据初始化与升级

- 编号 SQL 迁移文件随程序发布，启动时按版本初始化或升级数据库。
- 升级已有数据库前，先生成一致性备份。不能以直接复制运行中的主数据库文件替代一致性备份。
- 待执行的迁移及版本记录在一个事务中完成，迁移脚本须兼容这一执行方式。
- 备份或迁移失败时停止启动，保留数据并报告错误；不自动删除数据库重建。
- 数据库版本比程序支持的版本更新时，拒绝启动，不自动降级。
- 该流程用于应用升级的数据保护，不增加第一版的批量导入导出功能。

## 维护原则

- SQL 查询显式使用参数绑定，跨记录业务操作具有明确的事务边界。
- 通过数据库集成测试验证词条判重、关系组判重、成员移除、删除冲突与整次回滚等关键规则。
- 客户端的临时表单与选择状态优先就近维护，避免提前维护一份全局数据副本。

## 需求对技术设计的约束

- 词条及关系组的编辑可能涉及多条数据，删除冲突时必须整次不执行，需要可靠的事务边界。
- 搜索是连续片段包含匹配，英文忽略大小写；不能擅自换成分词检索或语义检索。
- 建组流程涉及搜索多选、临时选择状态、独立保存新词条及取消操作，应在前端方案评估中覆盖这些交互。
- 内存目标需要在选定技术栈后以代表性数据、空闲状态与常见操作实测，不能由框架名称推定。

## 运行访问边界

- Windows 默认仅监听本机回环地址，通过本机浏览器访问。
- 后续 Docker 中应用监听容器网络接口以供端口映射，默认部署示例仅将端口发布到宿主机回环地址。容器网络内的访问与宿主机端口发布是不同边界。
- 前端资源随程序本地提供，基本功能不依赖 CDN 或互联网服务。
- 本阶段不增加账号登录；以后若需要局域网或公网访问，再明确相应的访问范围与保护方式。

## 性能与交付验证计划

- 先验证最小运行链路：正式构建程序启动、前端资源提供、SQLite 访问与代表性的搜索和写入操作，再逐步补齐界面。
- 使用已确认的 1 万词条、3 万关系组验证规模，记录测试机器、系统、数据内容长度及运行版本。
- 分别记录启动峰值、空闲稳定状态、搜索与编辑负载下的后端进程内存，以及常见操作耗时；浏览器内存另行记录。100 MiB 保持为软目标，超出时先定位原因，再决定是否优化或调整预算。
- 验证数据重启后保留、删除冲突整次回滚、升级备份及失败迁移的数据保留。
- Docker 进入后续交付阶段时，再验证挂载目录持久化及容器运行表现。

## 已查证的候选方案依据

以下为选型期间查证的事实，包含已选方案及曾比较的替代方案；选择结果以“已确认的技术栈”为准。查询日期为 2026-11-03。

- Go 的标准库支持在编译时[嵌入静态文件](https://pkg.go.dev/embed)，Go runtime 随二进制交付；涉及 cgo 或动态链接时，仍需核对系统库依赖，见 [Go FAQ](https://go.dev/doc/faq#Why_is_my_trivial_program_such_a_large_binary)。
- SQLite 面向应用内的本地数据存储，无需独立数据库服务，并支持[事务原子性](https://sqlite.org/transactional.html)，符合当前单用户使用场景，见[适用场景](https://sqlite.org/whentouse.html)。选择它不代表性能和内存已经验证。
- [Vue 文档](https://vuejs.org/guide/extras/ways-of-using-vue.html)介绍了由客户端管理交互与状态的单页应用方式；[Vite](https://vite.dev/guide/build.html)可以构建供静态服务提供的文件。因此 Vue 前端不必引入常驻的 Node 服务，但采用该构建方案会增加前端开发和构建工具链。
- [htmx](https://htmx.org/docs/)通过 HTML 属性发起请求并更新页面片段，通常由服务器返回 HTML；使用它本身无需构建工具。它是服务端模板方案的候选，但复杂的客户端临时状态仍需设计。
- [Node 的单可执行文件机制](https://nodejs.org/api/single-executable-applications.html)允许分发到未预装 Node 的机器。因此不能仅以“用户必须安装 Node”为理由排除 TypeScript/Node 后端；具体打包限制和内存仍需验证。
- 后续 Docker 部署可通过[数据卷](https://docs.docker.com/engine/storage/volumes/)使数据独立于容器生命周期。若 SQLite 启用 [WAL](https://sqlite.org/wal.html)，还需考虑旁边的日志文件，应以数据目录为持久化边界，避免把运行中的主数据库文件视为完整备份。
- [modernc.org/sqlite](https://pkg.go.dev/modernc.org/sqlite) 提供不依赖 cgo 的 SQLite 驱动；其构建便利不代表内存或性能必然优于 cgo 驱动。
- [`net/http.ServeMux`](https://pkg.go.dev/net/http#ServeMux) 支持请求方法与路径参数，可作为当前接口的路由基础。
- Go 官方文档说明了[参数化查询](https://go.dev/doc/database/sql-injection)与[事务用法](https://go.dev/doc/database/execute-transactions)；事务内操作应通过同一个事务对象执行。
- [Vue Router](https://router.vuejs.org/)用于页面导航；Vue 官方提供[响应式状态管理方案与 Pinia 的适用说明](https://vuejs.org/guide/scaling-up/state-management.html)，可按共享状态需求决定是否引入全局状态库。
- SQLite 提供[一致性备份](https://www.sqlite.org/backup.html)，驱动也提供 [Backup API](https://pkg.go.dev/modernc.org/sqlite#Backup)。普通事务不能执行所有类型的维护 SQL，例如 [VACUUM](https://www.sqlite.org/lang_vacuum.html) 不可在活动事务内运行，迁移脚本必须遵守约定的事务边界。
- [Docker 端口发布文档](https://docs.docker.com/engine/network/port-publishing/)说明了容器端口与宿主机绑定地址的关系；默认部署示例应显式指定宿主机回环地址，而不是省略宿主机地址。
